# Faculty Work Diary – Government First Grade College, Channapatna

A mobile-friendly starter web application hosted on GitHub Pages and backed by Firebase Authentication + Cloud Firestore.

## Included
- Faculty, HOD and Principal role-based access
- Daily diary entry with Monday-based week grouping
- Draft and submit workflow
- HOD approve / return with remarks
- Principal college-wide dashboard
- Current-month and current-year report filters
- Excel (.xlsx), PDF and Word-compatible (.doc) exports
- Firestore security rules and suggested indexes

Departments: Physics, Chemistry, Mathematics, Computer Science, Botany, Zoology, Commerce and Arts.

## 1. Create Firebase project
1. Open https://console.firebase.google.com/ and create a project.
2. Add a Web App to the project and copy its Firebase web configuration.
3. In Authentication > Sign-in method, enable **Email/Password**.
4. In Firestore Database, create a database in production mode.
5. In Project settings > Your apps, copy the web config into `js/firebase-config.js`.
6. Replace all placeholder values. The web config is intended for client use; database security comes from Firestore Rules. Never put service-account keys in this repository.

## 2. Create user accounts and profiles
Create each user in Firebase Console > Authentication > Users > Add user. Then create a matching document in Firestore collection `users`, using the exact Authentication UID as the document ID.

Example faculty profile:
```json
{
  "displayName": "Faculty Name",
  "email": "faculty@example.com",
  "role": "faculty",
  "department": "Physics",
  "active": true
}
```

Example HOD profile:
```json
{
  "displayName": "Head of Department",
  "email": "hod@example.com",
  "role": "hod",
  "department": "Physics",
  "active": true
}
```

Example Principal profile:
```json
{
  "displayName": "Principal",
  "email": "principal@example.com",
  "role": "principal",
  "department": "College",
  "active": true
}
```

Allowed role values are exactly `faculty`, `hod`, `principal`. Department values must match one of the eight listed departments for faculty and HOD accounts. Principal may use `College`.

**Important:** Only a trusted college administrator should create profiles and assign roles. Never let users choose their own role. This starter app intentionally denies all client writes to `users`.

## 3. Deploy Firestore rules and indexes
1. Open Firestore Database > Rules.
2. Paste the contents of `firestore.rules` and click Publish.
3. If prompted to create a composite index, use the definitions in `firestore.indexes.json` or follow the Firebase error link.
4. Review the rules with the Firebase Rules Playground / Emulator before real deployment.

Storage is closed by default. This project does not currently upload files, so no Storage setup is required.

## 4. Upload to GitHub
1. Create a repository, for example `gfgc-faculty-work-diary`.
2. Extract this ZIP file on your computer.
3. Upload the contents of the `GFGC_Faculty_Work_Diary` folder to the repository root. `index.html` must be at the root.
4. Commit the files to the `main` branch.

## 5. Enable GitHub Pages
1. Open repository Settings > Pages.
2. Under Build and deployment, select **Deploy from a branch**.
3. Select branch `main` and folder `/ (root)`.
4. Save and wait for deployment.
5. Open the URL shown in Settings > Pages.

## 6. Test before college-wide use
- Sign in with a test faculty account and submit a diary.
- Confirm faculty can see only their own records.
- Sign in as the matching department HOD and approve / return the entry.
- Sign in as Principal and confirm college-wide records are visible.
- Test all three export formats.
- Test access from a phone.

## Important limitations / production checklist
- This is a functional starter implementation, not a full institutional ERP.
- One diary record per faculty member per date is intended. The starter uses a client-side check; for strict duplicate prevention, use a trusted backend/Cloud Function and a deterministic document ID.
- Weekly summaries are represented by the `weekStart` field and can be grouped in a future weekly-report view.
- Monthly and annual reports are generated by date filtering in the Reports tab.
- Word export is a Word-compatible `.doc` HTML document, not a native `.docx` file.
- The app currently uses Firebase web SDK compat CDN scripts and third-party CDN libraries for exports. A network connection is needed.
- For institutional production, add an administrator provisioning workflow using Cloud Functions / Admin SDK, audit logs, account recovery policy, backups, retention policy, and a formal security review.
- Firestore rules are security-critical. Test them against the exact roles and workflows before entering real faculty data.
- Do not store highly sensitive personal information in diary text fields.
